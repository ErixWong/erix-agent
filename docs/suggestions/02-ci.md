# chore(ci): add a minimal GitHub Actions workflow running the existing checks

## Background

The repo has strong local gates:
- `npm test`, which is `node --test` with 1100+ tests;
- `npm run check`;
- `check:docs`, `check:docs:strict`, `check:docs-examples` and `check:pack-links`.

Nothing runs them automatically, though. There is no `.github/workflows/` or any other CI config, and the release checklist in `AGENTS.md` is manual. #158 already notes that docs-sync-check "也未挂 CI" (isn't hooked into CI) and "可在 CI 里以 `--strict` 运行" (could run in CI with `--strict`). With about 13 commits a day and frequent minor releases, a red/green signal on every push and PR is cheap insurance, and it also covers AI-authored commits before a human reviews them.

Hosts are already relying on this. #183 shows touwaka runs erix's contract suite in its own CI, so a regression is currently caught downstream before it is caught here.

## Proposal

Add `.github/workflows/ci.yml` (sketch):

```yaml
name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [22, 24]   # engines: >=22
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "${{ matrix.node }}" }
      - run: npm run check
      - run: npm test
      - run: npm run check:docs
      - run: npm run check:docs-examples
      - run: npm run check:pack-links
```

Notes:
- There are zero runtime dependencies, so no `npm ci` step is needed (add one only if devDependencies appear).
- Start `check:docs:strict` as `continue-on-error: true` and promote it later, so that docs drift doesn't block code merges on day one.
- Optionally add a `windows-latest` / `macos-latest` job. Combined with the `/tmp` → `os.tmpdir()` cleanup (separate issue), it keeps the test suite portable.

## Acceptance

- Every push and PR shows a status check. `main` is green on Node 22 and 24.
- The README gets a CI badge (optional).

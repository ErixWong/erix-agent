# v0.0 Parallel Development Interface Contract (Scaffold Agreement; Three Workers Must Follow Strictly)

> Chinese version: [v0.0-contracts_cn.md](v0.0-contracts_cn.md)

> *Historical snapshot: this is the interface contract frozen for v0.0. It is preserved as a record and is not updated to match later releases.*

> Purpose: develop the providers / messages+tokens / store+loop tracks in parallel, with disjoint file sets,
> and use this document's exported signatures as the sole authority for cross-file references. Implementation details are unrestricted; signatures must not change.

## Shared Engineering Constraints (All Three Parties)

- Zero runtime dependencies, pure ESM (`"type": "module"`), Node 22+, no build step
- Use JSDoc typedefs for types; do not introduce TypeScript
- Tests: `node --test` + `node:assert/strict`; network access is prohibited (protocol tests use mock fetch)
- The standard error type is `KitError` (implemented by worker-1 in src/providers/errors.js); other modules may throw `new Error` directly; at the loop layer, nudge on a stall hit first, and stop normally with `termination.reason="stall"` after consecutive hits exceed the limit

## ① src/providers/errors.js (owned by worker-1)

```js
export class KitError extends Error {
  /** @param {string} code "timeout"|"rate_limited"|"auth"|"network"|"server"|"unknown"
   *  @param {string} message @param {{retryable?:boolean, status?:number, cause?:any}} [opts] */
  constructor(code, message, opts = {})
}
export function classifyHttpError(status, bodyText) // → KitError（429→rate_limited, 401/403→auth, 5xx→server, all others→unknown）
export function classifyFetchException(err)          // → KitError（AbortError/timeout→timeout, all others→network）
// retryable：timeout/rate_limited/server = true；auth/network=false（the caller decides whether to retry network errors）
```

## ⑤ src/loop.js (owned by worker-3; depends on the concepts from ②④ but does not import concrete implementations—provider/store are both injected)

```js
export async function runToolLoop({
  provider, system, initialUserMessage, initialMessages, // initialMessages takes precedence
  tools = [], executeTool, maxRounds = 8,
  stallDetection = { window: 4 },   // false disables; tool signature = name + JSON.stringify(input), compared against a sliding window
  store, runId, onRound, onToolResult, signal,
}) // → { finalText, messages, transcript, rounds, truncated, usage }
// Behavior: stopReason==="tool_use" → executeTool(name, input) one at a time, and feed each result back as a user message containing a tool_result block;
//   executeTool throws → tool_result is_error:true without interruption; onToolResult(name, result) may rewrite the result;
//   suspected stall hit → inject nudge; 3 consecutive hits → termination.reason="stall", return normally with truncated:true;
//   when maxRounds is exhausted → return with truncated:true and the current finalText;
//   each round store?.appendRound(runId, {round, messages: 本轮新增, ts})
// Message shape: canonical throughout internally (architecture.md §2); the provider handles serialization before invocation
```

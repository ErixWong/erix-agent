# v0.0 并行开发接口契约（脚手架约定，三个 worker 必须严格遵守）

> 目的：providers / messages+tokens / store+loop 三条线并行开发，文件集互不相交，
> 跨文件引用一律以本文件的导出签名为准。实现细节自由，签名不得改。

## 工程约束（三方共同）

- 零运行时依赖、纯 ESM（`"type": "module"`）、Node 22+、无构建步骤
- 类型用 JSDoc typedef，不引 TypeScript
- 测试 `node --test` + `node:assert/strict`，禁止访问网络（协议测试走 mock fetch）
- 错误类型统一 `KitError`（src/providers/errors.js，worker-1 实现），其他模块要抛错可直接 `new Error`；loop 层 stall 命中先 nudge，连续超限以 `termination.reason="stall"` 正常停止

## ① src/providers/errors.js（worker-1 拥有）

```js
export class KitError extends Error {
  /** @param {string} code "timeout"|"rate_limited"|"auth"|"network"|"server"|"unknown"
   *  @param {string} message @param {{retryable?:boolean, status?:number, cause?:any}} [opts] */
  constructor(code, message, opts = {})
}
export function classifyHttpError(status, bodyText) // → KitError（429→rate_limited, 401/403→auth, 5xx→server, 其余→unknown）
export function classifyFetchException(err)          // → KitError（AbortError/超时→timeout, 其余→network）
// retryable：timeout/rate_limited/server = true；auth/network=false（network 由调用方决定重试）
```

## ② src/messages/canonical.js（worker-2 拥有）

canonical 块格式见 docs/architecture.md §2。导出：

```js
// 序列化：canonical → OpenAI chat/completions 请求片段
export function canonicalToOpenAIMessages(system, messages) // → openai messages[]
export function canonicalToolsToOpenAI(tools)               // 规范 ToolSchema[] → openai tools[]（{type:"function",function:{name,description,parameters}}）
// 解析：OpenAI 非流式响应 JSON → ChatResponse
export function openAIResponseToCanonical(json)             // → { content: Block[], stopReason, usage? }
// stopReason 归一：stop→"end_turn"，tool_calls→"tool_use"，length→"max_tokens"，其余原样
```

ToolSchema 规范形态：`{ name, description?, inputSchema: <JSON Schema object> }`

## ⑤ src/loop.js（worker-3 拥有，依赖 ②④ 的概念但不 import 具体实现——provider/store 均注入）

```js
export async function runToolLoop({
  provider, system, initialUserMessage, initialMessages, // initialMessages 优先
  tools = [], executeTool, maxRounds = 8,
  stallDetection = { window: 4 },   // false 关闭；工具签名 = name + JSON.stringify(input) 滑动窗口比对
  store, runId, onRound, onToolResult, signal,
}) // → { finalText, messages, transcript, rounds, truncated, usage }
// 行为：stopReason==="tool_use" → 逐个 executeTool(name, input)，结果回喂为 user 消息 tool_result 块；
//   executeTool 抛错 → tool_result is_error:true 不中断；onToolResult(name, result) 可改写结果；
//   stall 疑似命中 → 注入 nudge；连续 3 次命中 → termination.reason="stall"，truncated:true 正常返回；
//   maxRounds 用尽 → truncated:true 返回当前 finalText；
//   每轮 store?.appendRound(runId, {round, messages: 本轮新增, ts})
// 消息形态：内部全程 canonical（architecture.md §2），调 provider 前的序列化由 provider 负责
```

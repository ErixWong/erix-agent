## C. Full loop FR-2 (worker-C, owns src/loop.js for this round)

All new parameters are optional; default behavior = v0.0 (completion defaults to false; retry/context are disabled by default):

```js
retry: { attempts = 2, backoffBaseMs = 1500, backoffMaxMs = 10000,
         sleepImpl = (ms) => new Promise(r => setTimeout(r, ms)) } | false,
completion: { signals = [], maxNoToolRounds = 3 } | false,   // default false (= v0.0 behavior)
context: { strategy, budgetTokens, keepRounds = 6 } | undefined,
maxTokenContinuations = 3,
```

- **FR-2.2 Snapshot retry**: before calling the provider each round, record `snapshotLen = messages.length`; on an error where `err.retryable === true`
  → restore the snapshot with `messages.length = snapshotLen` → sleep(min(base·2^n, max)) → retry; only rethrow after all attempts are exhausted.
  Non-retryable errors are thrown immediately. Retry is disabled by default (`false`) (v0.0 behavior).
- **FR-2.4 Completion signals** (enabled only when completion is not false): if this round has no tool_use and finalText contains any substring in signals → end normally;
  if there is tool history, no signal, and consecutive no-tool rounds < maxNoToolRounds → treat it as transitional text, inject the user message `"（please continue completing the task）"` and continue the loop;
  when consecutive no-tool rounds reach maxNoToolRounds → force termination and return (truncated:false).
- **FR-2.5 max_tokens continuation**: when stopReason==="max_tokens" → put the assistant's partial text into messages and call chat again directly for continuation
  (within the same round), concatenating the text into the same assistant block; continuation count is capped at maxTokenContinuations.
- **Merge adjacent assistant messages**: before each provider call, normalize messages—merge consecutive assistant messages into one (concatenate blocks) to prevent 400 errors.
  Idempotent and always enabled.
- **FR-2.6 Compaction hook**: before each provider call, if `context?.strategy` and `await strategy.shouldCompact(messages, context.budgetTokens)`
  → `const r = await strategy.compact(messages, { keepRounds: context.keepRounds, budgetTokens: context.budgetTokens })`
  → `messages = r.messages`; record `folded: true` + `foldedPayload: r.foldedPayload` (if present) for this round;
  accumulate into the returned `compactionStats: [{ compacted, foldedRounds, tokensBefore, tokensAfter }]`.
  **strategy is duck-typed only; do not import any concrete implementation from compact/*.**
- The return value adds `compactionStats` (default `[]`); all other fields remain unchanged. Add new tests in test/loop-fr2.test.js;
  modify the existing test/loop.test.js only if necessary (the goal is not to touch it).

## D. Compaction ①② + config (worker-D)

### src/messages/rounds.js

```js
export function groupIntoRounds(messages)
// → { head: CanonicalMessage[], rounds: [{ messages: CanonicalMessage[] }] }
// head = prefix through (and including) the first real user message; after that:
//   one round = assistant (possibly containing tool_use) + the immediately following user (tool_result blocks); a plain-text assistant is a standalone round;
//   a real user (not tool_result) is itself one unit (an exclusive round, ensuring folding never splits it)
// No orphans tolerated: assistant contains tool_use but the following user does not contain a matching tool_result (IDs do not match) → throw;
//   user contains tool_result but the preceding message is not an assistant with a matching tool_use → throw
```

## C. loop FR-2 全量（worker-C，本轮拥有 src/loop.js）

全部新参数可选，缺省行为 = v0.0（completion 缺省 false；retry/context 缺省不启用）：

```js
retry: { attempts = 2, backoffBaseMs = 1500, backoffMaxMs = 10000,
         sleepImpl = (ms) => new Promise(r => setTimeout(r, ms)) } | false,
completion: { signals = [], maxNoToolRounds = 3 } | false,   // 缺省 false（= v0.0 行为）
context: { strategy, budgetTokens, keepRounds = 6 } | undefined,
maxTokenContinuations = 3,
```

- **FR-2.2 快照重试**：每轮调 provider 前记 `snapshotLen = messages.length`；抛错且 `err.retryable === true`
  → `messages.length = snapshotLen` 恢复快照 → sleep(min(base·2^n, max)) → 重试；attempts 用尽才向上抛。
  非 retryable 立即抛。retry 缺省 false 不启用（v0.0 行为）。
- **FR-2.4 完成信号**（completion 非 false 才启用）：本轮无 tool_use 且 finalText 含 signals 任一子串 → 正常结束；
  有工具历史、无信号、连续无工具轮 < maxNoToolRounds → 视为过渡文本，注入 user 消息"（请继续完成任务）"继续循环；
  连续无工具轮达 maxNoToolRounds → 强制结束返回（truncated:false）。
- **FR-2.5 max_tokens 续写**：stopReason==="max_tokens" → assistant 部分文本入 messages，直接再调 chat 续写
  （同一轮内），文本拼入同一 assistant 块；续写次数上限 maxTokenContinuations。
- **相邻 assistant 合并**：每次调 provider 前归一化 messages——连续 assistant 消息合并为一条（块拼接），防 400。幂等，始终开启。
- **FR-2.6 压缩钩子**：每轮调 provider 前，若 `context?.strategy` 且 `await strategy.shouldCompact(messages, context.budgetTokens)`
  → `const r = await strategy.compact(messages, { keepRounds: context.keepRounds, budgetTokens: context.budgetTokens })`
  → messages = r.messages；本轮 record 记 `folded: true` + `foldedPayload: r.foldedPayload`（若有）；
  累计进返回的 `compactionStats: [{ compacted, foldedRounds, tokensBefore, tokensAfter }]`。
  **strategy 只做鸭子类型，禁止 import compact/* 具体实现**。
- 返回值新增 `compactionStats`（缺省 []），其余字段不变。新增测试放 test/loop-fr2.test.js；
  既有 test/loop.test.js 仅在必要时可动（目标是不动）。

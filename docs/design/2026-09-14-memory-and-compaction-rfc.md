## 1. 目的与范围

**目的**：从第一性原理重新审视 erix 的**折叠（compaction）**与**记忆（notes/recall/store）**，给出可实施的重构设计，供独立评审与分期落地。

**范围**：
- 折叠：选择策略、保留单位、注入契约、与取回的接口
- 记忆：notes 的定位、索引由谁生成、与 store.recall 的关系
- 可重放性：由谁声明、引擎如何机械执行
- **不在范围**：psyche/事前整形（ADR-010 已定：对话场景、冷循环+L3、非本期）；L2 向量检索（归宿主）

## 2. 第一性原理

### 2.1 折叠的定义
> **折叠不是"压缩"，是"有约束的信息销毁"。**

上下文预算有限，而对话与工具输出无界增长 → 必须销毁信息。由此得到四条原理：

| 编号 | 原理 | 推论 |
|---|---|---|
| **P1** | **销毁必须被选择** | 丢什么按「可恢复性 × 未来价值」决定，不能按"最旧/最大"机械决定 |
| **P2** | **销毁必须可见** | 消费上下文的一方必须知道"自己丢了什么"，否则会假设信息仍在（Memento 困境） |
| **P3** | **销毁必须可逆** | 能再取的只留**指针**（归档 + 定位），不留副本 |
| **P4** | **禁止"重推"当恢复手段** | 不可重放的值，重跑/重推会得到**不同答案** → 必须在销毁时保住值本身 |

### 2.2 两条判定法（本 RFC 的核心检验手段）

- **判定法 A（承重判定）**：
  > 把提示词**全部删掉**，正确性是否仍然成立？不成立 → 该机制承重错了。
- **判定法 B（可恢复性判定）**：
  > 这条信息**能否在没有信息损失的前提下重新获得**？能 → 可丢（留指针）；不能 → 必须保（留原话）。

### 2.3 三方责任（与 ADR-012 一致，本 RFC 细化）

| 角色 | 负责 |
|---|---|
| **引擎** | 真相（记录）与机械保证：销毁是可见的、可逆的、不撒谎的 |
| **模型** | 效率：决定"是否取回"（**不承担正确性**） |
| **宿主** | 策略：声明（工具效果、不可重放性）、跨 run 记忆（LTM/topics）、场景 profile 选择 |

| 能力 | 位置 | 事实 |
|---|---|---|

| 按范围取回 | `src/store/file.js` `recall(runId, fromRound, toRound, pattern)` | **服务端过滤后返回**（不是全量读回）✅ |

| 折叠地址 | `src/compact/fold-statistical.js:213` `roundRangeForIndexes` | 已算出被折轮次范围 `{from,to}`（**但没被用作索引**） |
| 工具输出归档 | `bin/tools.js` | >800 字符落 `<transcriptDir>/outputs/<runId>/NNN-exec.txt` + `.meta.json` |
| recall 工具（库） | `src/tools/recall.js`（`createRecallTool`） | 库里有、宿主可用；**CLI 不暴露**（PR #60 实测 28 会话 0 调用后移除） |
| notes 技能 | `skills/notes/skill.mjs` | run scope、pull-only、`current + superseded[≤3] + folded`、墓碑 |

### 3.2 已知缺陷（本程实测，逐条带证据）

| # | 缺陷 | 证据 |
|---|---|---|
| **D1** | **折叠会丢掉后续需要的真值**，且不留地址 | e2e：首次执行 `nonce=hzmk…`，折叠后模型无法取回；重跑得到 `O2D4…` 并当作原值回答（静默错答） |
| **D2** | **保护判据按角色，不按可恢复性** | `bin/config.js:131` `protectedMessage: isRealUser`；`selectFoldedRounds` 只跳过含真实用户发言的轮 → **agent 自己的决策/结论被折进有损摘要**；coding 场景下"用户发言"极少，保护几乎无收益 |
| **D3** | **可重放性由引擎猜**（写死正则） | `bin/tools.js:38-44` `NON_REPLAYABLE_COMMAND_PATTERNS`（`/dev/urandom`、`$RANDOM`…）+ `:713` `replayable = name !== "exec" \|\| !isNonReplayableCommand(command)` |
| **D4** | **重跑拦截按"完全相同的命令串"** → 可被改写绕过 | e2e 实测：模型把命令包成 `bash -lc 'set -euo pipefail …'` → 拦截未触发 → 拿到新值 |
| **D5** | **索引/契约被删过头**：删"值索引注入"时把**唯一的导航索引**也删了 | 现在折叠后模型无目录；实测它去 `tree`/`readFile` 无界浏览（2–6 个归档/run），并调 `note_read` 6–21 次/run |
| **D6** | **折叠产物与 guard 耦合** → guard 默认关后，"丢失可见"与归档索引**一并消失** | `bin/final-guard.js:261` 是 `[本 run 状态]` 的唯一生成处；`bin/cli.js` 未传 `stubFor` → 折叠 stub **死代码**（pilot 中 `[已折叠]` 出现 0 次） |
| **D7** | **notes 作为折叠解由模型自写** → 依赖元认知（该记 + 该查） | 实测：接线修复后会被调用（3 次/run），但**不能承重**；而接线前 0/24 是接线 bug 的假象 |
| **D8** | **模型失败的主因是"不收敛"而非"不查证"** | 矩阵：30/30 打满轮次、`noAnswer 100%`，但 `note_read` 仍被调用；修复后（轮次上限放宽 + stub/契约）pilot 3/3 正确、轮次 7/6/14 |

### 3.3 方法论教训（影响本 RFC 的可验证性设计）

| 教训 | 证据 |
|---|---|
| 大样本探针**信息/成本比极差** | 300+ 次调用、一次实验被接线 bug 污染作废、两次撞地板效应（100% 不回答） |
| **确定性测试 + 1–3 次 pilot** 才是有效武器 | 接线 bug（工具未进 schema）、guard 误杀/漏检、重跑值交付，全部由确定性探针或单次 e2e 发现 |
| 凡批量跑数必须**先报成本并取得确认** | 实际消耗曾达预估 2.5×（deepseek 打满轮次） |

## 4. 目标架构

### 4.1 四层模型

```
Tier 0  真相层：messages / transcript          —— append-only，永不销毁（折叠只从"视野"移除）
Tier 1  索引层：销毁时构建的条目                —— 值(原话) / 决策(原话) / 约束(原话) / 地址(轮次范围、文件)
Tier 2  上下文：最近 N 轮 + Memento 契约（Tier 1 的摘录，替换式）
Tier 3  取回层：按【地址】取【有界切片】         —— 复用 store.recall(fromRound,toRound,pattern)
```

**类比（数据库）**：Tier 0 = 数据表/WAL；Tier 1 = 索引（避免全表扫描）；**索引不是真相**，错了/缺了都能从 Tier 0 兜底；绝不能用索引替代真相。

### 4.2 保留单位：从「轮/消息」改为「条目」

| 条目类型 | 判据 | 处理 |
|---|---|---|
| **不可重放值** | 判定法 B：无法无损重建 | **保原值**（确定性 stub，不过 LLM） |
| **决策/承诺/约束** | 不可重建（原话即是真相） | **保原话**（有界截取，确定性） |
| **可再取回的原文** | 工具输出、文件内容 | **只留指针**（归档路径 + locator） |
| **可推导/冗余** | 重复探测、铺垫 | **直接丢** |

### 4.3 策略矩阵（多策略，按场景选择）

| 策略 | 保留什么 | 适合 | LLM 成本 | 漂移风险 |
|---|---|---|---|---|
| **A 指针式**（墓碑） | 索引 + 指针，无内容 | coding（输出都可再取） | 0 | 无 |
| **B 事实清单**（确定性） | 值 + 决策 + 约束（原话）+ 指针 | **coding / agent 循环（建议主路径）** | 0 | 无 |
| **C 叙事摘要** | LLM 写的连贯摘要 | 长发散 chat（叙事连续性有价值） | 每折 1 次调用 | **有**（会编/会漏） |
| **D 段索引 + recall** | 段地址 + 标题；按需取原文 | 发散 chat（宿主 topics） | 索引便宜 | 低 |
| **E 纯滑窗** | 最近 N 轮原文 | 极短任务 | 0 | 无 |
| **F 大声失败** | 不保证，显式报错 | 预算小到无法保证 | 0 | 无（必须显式） |

**profile 默认**：
- `coding` = **A + B**（零 LLM、零漂移；LLM 摘要**不作默认**）
- `chat` = **C + D**（叙事连续性本身有价值，值得一次 LLM 调用）

### 4.4 Memento 契约（证据式，**非承重**）

折叠时**替换式**注入（不逐轮追加，避免膨胀与坏前缀缓存）：

```
[你的处境 · 证据]
· 你现在的视野：最近 N 轮 + 下列已保留条目
· 已丢弃（可再取回）：工具输出原文 → 归档 003-exec.txt / 004-exec.txt
· 不可重放（重建会得到不同值；引擎不会让你拿到假值）：
    nonce=abc123（首次执行，001-exec.txt）
· 已保留的决策/约束：
    #1 采用方案 B（原因：…）
    #2 用户要求不动 X 文件
· 段索引（需要原文时按地址取回）：
    #1 需求确认(轮3–8)   #2 部署讨论(轮12–18)  → recall #2
```

**定位**：这段文本描述的是**世界状态（证据）**，不是"模型必须遵守的规则"。它只带来**效率**（少烧轮次），**不承担正确性**（判定法 A：删掉它，正确性必须仍成立）。

### 4.5 可重放性：由生产者声明

| 层 | 声明者 | 形式 |
|---|---|---|
| 工具级 | 工具生产者（宿主/skill 作者） | 工具 schema 增加 `replayable: true\|false`（或 `effect: "read"\|"write"\|"generate"`） |
| exec 命令级 | 宿主 policy | `nonReplayable: { patterns?: RegExp[], classify?: (cmd) => boolean }`（命令串动态，只能由平台策略定） |
| 兜底 | 引擎内置规则 | 保留现有正则列表作为 **fallback**，并标注来源：`replayableSource: "declared" \| "policy" \| "heuristic"` |

### 4.6 引擎的机械保证（不需要模型配合）

1. **不可重放的值不离开上下文**：折叠时以 stub 保留原值
2. **重复执行不返回"新值"**：按**声明类别**（而非完全相同命令串）拦截，直接从记录回答
3. **真跑了也要标注**：结果附"这是重跑，原值 X（001-exec.txt）"
4. **越界即失败**：预算过小无法保证时，选择**大声失败**（F），不静默降级

> 明确：**可重放性不由引擎猜、更不由模型记**。平台声明它，引擎消除需要判断的场景。

## 6. 验证方案（先 pilot，后放大）

### 6.1 确定性测试（每策略）
折叠后：保留条目是否符合 P1 分类；stub 是否含原值且**不含凭据**；索引是否**有界**且**不含值**；多次折叠是否**替换**而非膨胀；按地址取回是否返回**正确轮次范围**。

### 6.2 coding 型可判任务（客观判据）
| 任务 | 判据 |
|---|---|
| **T1 非重放值回溯** | 终稿值 == 首次执行值；**且无重跑** |
| **T2 决策回溯** | 能说出"选了哪个、为什么"；**不与先前决策矛盾** |
| **T3 约束回溯** | 折叠后仍遵守"不动 X 文件" |
| **T4 不可恢复** | 明确声明"不可恢复"，**不得编造** |

**流程**：3–5 次 pilot 判断是否可区分（非地板/天花板）→ 仅在可区分时放大；放大前报模型/调用数/成本预估并取得确认。

### 6.3 chat 场景
交宿主（touwaka topics + 人工判分）；erix 只保证机械部分（保址、索引、一步取回）。

## 7. 重构分期

| 期 | 内容 | 破坏性 |
|---|---|---|
| **P0（修缺陷，不改变架构）** | 修 D6（stub/索引接线，脱离 guard）；D4（按声明类别拦截）；D3（policy 接口 + 来源标注）；D5（折叠时给**有界导航索引**） | 低 |
| **P1（索引与契约）** | 折叠时生成 **Tier 1 条目索引**（值/决策/约束/地址，确定性、有界、替换式）；注入 Memento 契约；接 `store.recall` 做有界取回；保护判据由**角色**改为**可恢复性**（D2） | 中（折叠产物结构变化） |
| **P2（策略化）** | `foldProfile: "coding" \| "chat"`（A+B / C+D）；策略 F（大声失败）；profile 化默认值 | 中（新增配置面） |
| **P3（验证与收敛）** | 按 T1–T4 验证；据此删减无人使用的机制（如 notes 若被 Tier 1 完全替代则降级为可选语义补充） | 低 |

## 8. 开放问题（请评审重点回答）

1. **Tier 1 索引的抽取规则**：决策/约束的"原话截取"如何避免噪声与误判？是否需要宿主提供抽取器？
2. **段索引的粒度**：按轮次范围是否够用？是否需要宿主注入 topic 边界（touwaka topics）？
3. **保护判据改为可恢复性后，预算压力如何分配**：是否会出现"什么都想保 → 保不住"？降级顺序应如何定义？
4. **notes 的去留**：Tier 1 自动索引是否已使 notes（作为折叠解）多余？保留语义补充是否值得？
5. **profile 默认值**：coding 默认 A+B（无 LLM 摘要）是否会损害某些长 coding 会话？
6. **与 ADR-010 的 psyches 边界**：本 RFC 是否需要修改 ADR-010 的表述？
7. **迁移与兼容**：折叠产物结构变化对宿主的影响（`recoveryHint`/`onAfterFold` 契约）？

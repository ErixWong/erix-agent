# v0.2 Parallel Development Interface Contract (Three workers must follow strictly)

> Chinese version: [v0.2-contracts_cn.md](v0.2-contracts_cn.md)

> *Historical snapshot: this is the interface contract frozen for v0.2. It is preserved as a record and is not updated to match later releases.*

> Continuing the v0.0/v0.1 pattern: file sets are disjoint; cross-file references follow this contract.
> **All existing tests must remain green** (except for the fold-statistical snapshot wording that worker-B is authorized to update).
> Specification sources: ADR-001/002/003/005/006/007 + issue #5.

## Shared engineering constraints

- Zero runtime dependencies, pure ESM, Node 22+; JSDoc typedefs; `node --test` + `node:assert/strict`; unit tests must not use the network
- Reuse KitError from src/providers/errors.js for errors (read-only); reuse token estimation from src/tokens.js (read-only)
- Reuse enforce-size from src/compact/enforce-size.js (read-only): `enforceSize(fields, budgetTokens)`, fields=[{key,text,priority}] (lower priority number = more important) → {fields, prunedKeys, tokensBefore, tokensAfter}

## A. file store + loop resume (worker-A)

### src/store/file.js

```js
export function createFileTranscriptStore({ dir })
// → { appendRound(runId, record), load(runId), recall(runId, fromRound?, toRound?, pattern?) }
// - File: dir/<runId>.jsonl (sanitize runId for use as a filename: retain only [A-Za-z0-9._-], replace everything else with _); recursively mkdir dir
// - appendRound: append-write JSON.stringify(record)+"\n" (fs.appendFile)
// - load: read by line and JSON.parse each line; **tolerate an incomplete final line** (a crash may write only half: discard the trailing fragment after the last complete newline); empty file → []
// - recall: semantics aligned with the memory store (range filtering + pattern substring filtering, with the same textification rules), read line by line without retaining the entire file in memory
// RoundRecord = { round, messages, folded?, ts?, foldedPayload? }（ADR-002）
```

### src/loop.js (this round only adds resume; do not change any other logic)

```js
// New parameter: resume = false (default; v0.1 behavior is unchanged)
// When resume=true and store/runId exist:

//   - Continue rounds from records.length; append the store snapshot each round as usual

### src/compact/fold-llm.js (new)

export const SUMMARIZER_PROMPT_GUIDE = `…` // Template guide for the caller writing the summarizer prompt (constant string), requiring the output:
//   ## Stage / ## Files changed / ## Verified items / ## Next steps (do not redo completed items) / ## Keywords (breadcrumbs)
//   + recall trace: when the folded rounds contain recall tool results, record "already recalled '<pattern>' at round X (conclusion: …)"
//   + End-of-summary recall guidance: "earlier rounds were folded; use recall(fromRound: a, toRound: b) to retrieve the original text"
export function createFoldLlmStrategy({ summarizer, maxSummaryTokens = 800 })
// summarizer: async ({ messages, roundRange: {from, to} }) => string (injected by the caller, using the fold-slot model)
// compact(messages, { keepRounds, budgetTokens }):
//   Grouping/retention logic is the same as fold-statistical (see src/compact/fold-statistical.js and src/messages/rounds.js; do not modify rounds.js);
//   folded rounds → summarizer → summary text;
//   Apply deterministic size enforcement to the summary: first split into sections by "## " (if it cannot be split, truncate the whole text by tokens),
//   use enforceSize to prune to maxSummaryTokens by priority—next steps/do not redo > verified items > files changed > keywords > stage narrative;
//   add the summary as a text block to the end of head, before the real user-message prefix (the same prepend approach as fold-statistical; it may be implemented without importing it);
//   foldedPayload = original content of the folded rounds; return CompactResult
```

## C. tools subpath (worker-C)

package.json already maps `"./tools": "./src/tools/index.js"`. Everything must be zero-dependency pure node (`rg`/`tree` implemented in-house; do not invoke external commands).

### src/tools/registry.js (ADR-006)

```js
export function createToolRegistry({ executors, schemas })
// → { executeTool(name, input), resolveTools(provider, sel) }
// executeTool: first perform minimal validation against schemas (missing required fields/type mismatch/maxLength exceeded) → **return an error string on validation failure; do not call the executor**;
//   on success → executors[name](input); executor errors propagate upward (the loop converts them to tool_result is_error)
// resolveTools(provider, sel): every schema.name returned by provider.listTools(sel) must have a registered executor,
//   otherwise throw KitError("tool_unknown_executor", name) (fail closed); the provider may override description and
//   inputSchema constraints (only tightening is allowed: smaller maxLength/more required fields); return the merged intersection with the registry schemas
```

### src/tools/providers.js

```js
export function createStaticToolProvider({ sets })        // sets: { default: ToolSchema[], ... }; listTools(sel) → sets[sel?.set] ?? sets.default
export function createJsonFileToolProvider({ path })      // File shape is also { sets: {...} }; read the file on every listTools call
export function createCompositeToolProvider({ providers }) // Merge in array order; later providers override description/constraints of same-named tools
```

### src/tools/recall.js (ADR-007: pattern first)

```js
export function createRecallTool({ store, runId, limits = {} })
// → { schema: ToolSchema, execute: (input) => Promise<string> }
// input: { pattern?, fromRound?, toRound?, offset? } (episodeId is reserved for v1.x and does not appear in the schema)
// No arguments → round overview: one line per round (round/folded marker/message count/tool-name summary) + fold watermark
// pattern → preferred path: full-range search, grep -C excerpts (matching line ±2 lines), ≤300tok per excerpt, at most 5 excerpts, ≤1500tok total (limits may override);
//   textification rules are the same as store.recall; above the cap, prepend "[截断，共 N 段，offset=5 继续]" ("truncated; N segments total; continue at offset=5")
// fromRound/toRound → original text for the range (textify messages round by round, with the same total hard cap and marker)
// Empty result → "未命中。建议换更短的关键词或同义词重试" ("No match; try a shorter keyword or synonym")
// Textification: text blocks use text; tool_use uses name+JSON.stringify(input); tool_result uses content
```

### src/tools/index.js

Export createToolRegistry, the three ToolProviders, and createRecallTool.

Tests: under test/tools/, registry (validation failure does not touch the executor—assert with a counting executor/fail closed/tightening overrides), providers, and recall (memory store data: three states/hard cap/marker/empty result). No network anywhere.
